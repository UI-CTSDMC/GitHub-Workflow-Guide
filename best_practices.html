Best Practices

Follow these guidelines to keep your GitHub workflow organized, secure, and consistent.

Repository Security

Keep sensitive research data, results, and credentials out of GitHub. Store them only in approved locations.

Branch Management

Lead and Validator should work independently on separate branches. Always verify your current branch before making changes.

File Organization

Use clear, consistent file and folder names. Keep only project-related code and approved documentation in the repository.

Commit and Push Practices

Write meaningful commit messages and push changes regularly to maintain a clear version history.

Commit Messages

Follow the Conventional Commits format to keep commit messages consistent. For example:

  • feat: add baseline analysis dataset
  • fix: correct missing value handling
  • docs: update analysis documentation

Copilot can help you draft commit messages in this format, especially when you're getting started.

When to Commit

At a minimum, commit after each major step of an analysis, such as creating an analysis dataset, completing an analysis specified in the SAP, or generating a key figure or table. You can commit more frequently for bug fixes and intermediate code revisions.

Review and Merge Approval

Resolve discrepancies before merging. Only approved materials from the Lead branch should be merged into main, following the project's established approval requirements.

Validation Records and Retention

Preserve required validation evidence. Retain or delete working branches according to project requirements. The Validator branch is not merged into main.
